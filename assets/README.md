# موقع ترتيبات ضيوف إمارة منطقة مكة المكرمة — نسخة Firebase

الموقع مبني على جزئين:
- **`editor.html`** — لوحة تحكم يفتحها فريق المحتوى مباشرة بدون تسجيل دخول، ويعدّل فيها كل شيء عبر نماذج بسيطة، ثم يضغط "نشر التحديثات".
- **`index.html` / `schedule.html` / `day.html` / `prayer-times.html`** — الصفحات التي يشاهدها الحضور، وتقرأ آخر نسخة منشورة تلقائيًا.

فريق المحتوى لا يحتاج الدخول إلى GitHub إطلاقًا، ولا حساب، ولا كلمة مرور — يكفي فتح رابط `editor.html`، التعديل، ثم النشر.

---

## ⚠️ لا يوجد تسجيل دخول — كل من يملك رابط `editor.html` يستطيع التعديل والنشر

بما إنه ما فيه خطوة تسجيل دخول، أي رابط `editor.html` يوصل له أي شخص = يقدر يعدّل وينشر تحديثات على الموقع اللي يشوفه الحضور، مو بس يشاهد. هذا غير `index.html` (رابط الحضور) الذي كان دائمًا مفتوحًا للقراءة فقط لأي أحد يعرفه — الفرق الآن إن حتى **التعديل** صار بلا حاجز، وليس القراءة فقط.

عمليًا هذا يعني: شاركي رابط `editor.html` فقط مع فريق المحتوى الموثوق، ولا تنشريه في أي مكان عام. إذا احتجتِ لاحقًا حماية حقيقية لمن يقدر يعدّل (وليس فقط من يقدر يشاهد)، الحل يرجع لإضافة تسجيل دخول من جديد.

---

## الخطوة ١: إنشاء مشروع Firebase (تُنفَّذ مرة واحدة فقط)

1. الدخول إلى [console.firebase.google.com](https://console.firebase.google.com) بحساب Google.
2. **Add project** ← اسم مثل `hajj-1447` ← إكمال الإعداد (يمكن تعطيل Google Analytics، غير ضروري).
3. من القائمة الجانبية: **Build → Firestore Database** ← **Create database** ← اختيار **Start in production mode** ← اختيار أقرب موقع سيرفر (مثل `eur3` أو `me-central1` إن توفر) ← **Enable**.
4. بعد إنشاء القاعدة، فتح تبويب **Rules** أعلى الصفحة واستبدال المحتوى بهذا بالضبط ثم **Publish** (لاحظي إن الكتابة مفتوحة بدون تحقق من هوية، بما إنه ما فيه تسجيل دخول):
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /hajj_data/content {
         allow read: if true;
         allow write: if true;
       }
     }
   }
   ```
5. من ⚙️ (إعدادات المشروع) أعلى القائمة الجانبية ← **Project settings** ← التمرير لأسفل حتى **Your apps** ← الضغط على أيقونة الويب `</>` ← تسمية التطبيق بأي اسم ← **Register app**. يظهر كائن `firebaseConfig` يحتوي على قيم مثل apiKey و projectId.
6. فتح `assets/firebase-config.js` في الموقع ووضع نفس القيم مكان القيم الحالية لكل سطر، ثم الحفظ.
7. رفع كل الملفات (بما فيها `assets/firebase-config.js` المعدَّل) على GitHub بنفس الطريقة المعتادة (Add file → Upload files → Commit).

بعد ذلك يصبح الموقع جاهزًا بالكامل.

## الخطوة ٢: كيف يعمل فريق المحتوى (في كل مرة)

1. فتح رابط `.../editor.html` (ضمن نطاق الموقع نفسه) — يفتح مباشرة بدون أي تسجيل دخول.
2. **الصفحة الرئيسية**: تعديل الترحيب، اسم الجهة، السنة، وجهات الاتصال — كل خانة فيها مثال بلون رمادي فاتح يوضّح الشكل المطلوب.
3. **الأيام والفعاليات**:
   - **التاريخ**: مربعان قابلان للاختيار من تقويم منبثق، تمامًا بنفس الطريقة — واحد ميلادي وواحد هجري. الاختيار من أي واحد فيهما يملأ الثاني تلقائيًا (لأنهما نفس اليوم)، ويملأ اسم اليوم بالأسبوع تلقائيًا أيضًا. ملاحظة: عرض التقويم الهجري داخل مربع الاختيار نفسه يعتمد على المتصفح (يظهر بشكل كامل في متصفحات Chrome / Edge الحديثة)، لكن اختيار التاريخ يعمل بشكل صحيح في كل الأحوال.
   - **لون اليوم**: اختيار من مجموعة ألوان جاهزة بأسماء عربية طبيعية (كحلي، أزرق مخضر، أخضر زيتوني...)، أو الضغط على "+" لاختيار أي لون آخر من منتقي الألوان الكامل.
   - **الفعاليات**: زر "+ إضافة فعالية" لكل يوم. خانة "تصنيف الفعالية" حرة تمامًا — يُكتب فيها أي نص (تحرك، تجمع، وجبة، أو أي تسمية أخرى)، ويظهر كما كُتب بالضبط تحت عنوان الفعالية. اختيار الأيقونة المرئية (الدائرة الملوّنة) منفصل تمامًا ويكون من شبكة أيقونات صغيرة أسفل خانة التصنيف.
   - لصق رابط خرائط قوقل في خانة "رابط الموقع" يضيف أيقونة موقع قابلة للضغط على الصفحة العامة.
4. زر **معاينة** يعرض كل صفحة من صفحات الموقع (الرئيسية، الجدول، كل يوم، وأوقات صلاة كل يوم) تمامًا كما تظهر للحضور.
5. زر **نشر التحديثات** ينشر التغييرات فورًا — الرابط نفسه الذي يستخدمه الحضور يتحدث تلقائيًا دون الحاجة لإرسال رابط جديد.
6. زر **تصدير PDF** يبني نفس صفحات الموقع بالضبط (الرئيسية، الجدول، صفحة كل يوم، وصفحة أوقات صلاة كل يوم منفصلة، بنفس التصميم والألوان تمامًا) ثم يفتح نافذة طباعة المتصفح لحفظها كملف PDF. هذا يعطي خيارًا ثانيًا لإرسال المحتوى للحضور غير الرابط المباشر: إما رابط الموقع الذي يتحدث تلقائيًا، أو ملف PDF ثابت بنفس الشكل يُرسل كمرفق.

## ملاحظات عامة
- لا حاجة لتعديل `assets/style.css` أو `assets/main.js` أو `assets/data-store.js` — هذه التصميم والبنية الثابتة فقط.
- الشعار الرسمي موجود بالفعل في `assets/logo.png`. لتغييره، يكفي رفع صورة PNG بنفس الاسم فوقه من GitHub.
- كل التعديل يتم بالكامل داخل `editor.html`، ولا حاجة لملفات CSV بعد الآن.
