# موقع ترتيبات ضيوف إمارة منطقة مكة المكرمة — نسخة Firebase

الموقع الآن مبني على جزئين:
- **`editor.html`** — لوحة تحكم يدخلها فريق المحتوى بعد تسجيل الدخول، يعدّلون فيها كل شي بنماذج بسيطة، ويضغطون "نشر التحديثات".
- **`index.html` / `schedule.html` / `day.html` / `prayer-times.html`** — الصفحات اللي يشوفها الحضور، تقرأ آخر نسخة منشورة تلقائيًا. ما فيه ملفات CSV تعدّل يدويًا بعد الحين.

فريق المحتوى ما يحتاجون يدخلون GitHub إطلاقًا. يفتحون رابط `editor.html` بس، يسجلون دخول، يعدّلون، وينشرون.

---

## ⚠️ نفس ملاحظة الخصوصية اللي لازم تكون واضحة

تسجيل الدخول الحين يحمي **من يقدر يعدّل** (بس اللي عنده حساب). لكن **قراءة** بيانات الحضور (الصفحة الرئيسية، الجدول، أرقام الجوالات) تبقى مفتوحة لأي شخص يعرف الرابط، لأن ما فيه سيرفر خلفي حقيقي يتحقق من هوية الزائر — هذي طبيعة أي موقع Static (حتى مع Firebase). لو الحساسية تتطلب حماية القراءة نفسها، الحل يحتاج فعليًا نظام تسجيل دخول للحضور أنفسهم، وهذا أكبر بكثير من نطاق الموقع الحالي.

---

## الخطوة ١: إنشاء مشروع Firebase (تسويها إنتِ مرة وحدة بس)

1. روحي [console.firebase.google.com](https://console.firebase.google.com) وسجلي دخول بحساب Google.
2. **Add project** → اسم أي شي مثل `hajj-1447` → أكملي الإعداد (تقدرين توقفين Google Analytics، مو ضروري).
3. من القائمة الجانبية: **Build → Firestore Database** → **Create database** → اختاري **Start in production mode** → اختاري أقرب موقع سيرفر (مثل `eur3` أو `me-central1` إذا متوفر) → **Enable**.
4. بعد ما ينشئ القاعدة، افتحي تبويب **Rules** بالأعلى واستبدلي المحتوى بهذا بالضبط ثم **Publish**:
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /hajj_data/content {
         allow read: if true;
         allow write: if request.auth != null;
       }
     }
   }
   ```
5. من القائمة الجانبية: **Build → Authentication** → **Get started** → فعّلي مزوّد **Email/Password**.
6. بتبويب **Users** بنفس الصفحة، اضغطي **Add user** وسوي حساب واحد تشاركينه مع فريق المحتوى (إيميل وكلمة مرور بسيطة تعطينهم إياها بأي وسيلة توثقين فيها إنه نفس الفريق).
7. من ⚙️ (إعدادات المشروع) بأعلى القائمة الجانبية → **Project settings** → مرري لتحت لين **Your apps** → اضغطي أيقونة الويب `</>` → سمي التطبيق أي اسم → **Register app**. بيطلع لك كائن `firebaseConfig` فيه قيم مثل apiKey و projectId.
8. افتحي `assets/firebase-config.js` بالموقع وحطي نفس القيم مكان `"ضعي_القيمة_هنا"` لكل سطر، واحفظي.
9. ارفعي كل الملفات (بما فيها `assets/firebase-config.js` المعدّل) على GitHub بنفس الطريقة المعتادة (Add file → Upload files → Commit).

بعد كذا الموقع شغّال بالكامل.

---

## الخطوة ٢: كيف يشتغل فريق المحتوى (كل مرة)

1. يفتحون رابط `.../editor.html` (نفس نطاق الموقع).
2. يسجلون دخول بالإيميل وكلمة المرور اللي سويتيها لهم بالخطوة ١-٦.
3. **الصفحة الرئيسية**: يعدّلون الترحيب، اسم الجهة، السنة، جهات الاتصال.
4. **الأيام والفعاليات**: لكل يوم — يضيفون/يحذفون فعاليات بزر "+ إضافة فعالية"، يختارون التصنيف من قائمة، يكتبون الوقت والعنوان والملاحظات، ويلصقون رابط قوقل ماب في خانة "رابط الموقع" لو حابين أيقونة الموقع القابلة للضغط تطلع.
5. زر **معاينة** يوريهم الشكل النهائي بالضبط زي ما بيطلع للحضور.
6. زر **نشر التحديثات** ينشر التغييرات فورًا — نفس الرابط اللي عند الحضور يتحدث تلقائي، بدون ما يرسل لهم رابط جديد.
7. زر **تصدير PDF** يفتح نافذة طباعة المتصفح لحفظ نسخة PDF من كامل الجدول لو حابين يرسلونها بدل/مع رابط الموقع.

## ملاحظات عامة
- لا تحتاجون تلمسون `assets/style.css` أو `assets/main.js` أو `assets/data-store.js` — هذي التصميم والبنية الثابتة فقط.
- الشعار الرسمي موجود بالفعل في `assets/logo.png`. لو حبيتي تغيّرينه، ارفعي صورة PNG بنفس الاسم فوقه.
- كل تعديل يصير بالكامل داخل `editor.html`، ما فيه حاجة لملفات CSV بعد الحين.
