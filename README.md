# موقع ترتيبات ضيوف إمارة منطقة مكة المكرمة — نسخة Firebase

الموقع مبني على جزئين:
- **`editor.html`** — لوحة تحكم يدخل إليها فريق المحتوى بعد تسجيل الدخول، ويعدّل فيها كل شيء عبر نماذج بسيطة، ثم يضغط "نشر التحديثات".
- **`index.html` / `schedule.html` / `day.html` / `prayer-times.html`** — الصفحات التي يشاهدها الحضور، وتقرأ آخر نسخة منشورة تلقائيًا. لا توجد ملفات CSV تُعدّل يدويًا بعد الآن.

فريق المحتوى لا يحتاج الدخول إلى GitHub إطلاقًا — يكفي فتح رابط `editor.html`، تسجيل الدخول، التعديل، ثم النشر.

---

## ⚠️ ملاحظة الخصوصية نفسها تبقى قائمة

تسجيل الدخول يحمي **من يستطيع التعديل** (فقط صاحب الحساب). أما **قراءة** بيانات الحضور (الصفحة الرئيسية، الجدول، أرقام الجوالات) فتبقى متاحة لأي شخص يعرف الرابط، لأنه لا يوجد سيرفر خلفي يتحقق من هوية الزائر — هذه طبيعة أي موقع Static حتى مع Firebase. إذا كانت الحساسية تتطلب حماية القراءة نفسها، فالحل يحتاج فعليًا نظام تسجيل دخول للحضور أنفسهم، وهذا أكبر من نطاق الموقع الحالي.

---

## الخطوة ١: إنشاء مشروع Firebase (تُنفَّذ مرة واحدة فقط)

1. الدخول إلى [console.firebase.google.com](https://console.firebase.google.com) بحساب Google.
2. **Add project** ← اسم مثل `hajj-1447` ← إكمال الإعداد (يمكن تعطيل Google Analytics، غير ضروري).
3. من القائمة الجانبية: **Build → Firestore Database** ← **Create database** ← اختيار **Start in production mode** ← اختيار أقرب موقع سيرفر (مثل `eur3` أو `me-central1` إن توفر) ← **Enable**.
4. بعد إنشاء القاعدة، فتح تبويب **Rules** أعلى الصفحة واستبدال المحتوى بهذا بالضبط ثم **Publish**:
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /hajj_data/content {
         allow read: if true;
         allow write: if request.auth != null;
       }
     }
   }
   ```
5. من القائمة الجانبية: **Build → Authentication** ← **Get started** ← تفعيل مزوّد **Email/Password**.
6. بتبويب **Users** بنفس الصفحة، الضغط على **Add user** وإنشاء حساب واحد يُشارَك مع فريق المحتوى (بريد إلكتروني وكلمة مرور بسيطة تُعطى لهم بأي وسيلة موثوقة).
7. من ⚙️ (إعدادات المشروع) أعلى القائمة الجانبية ← **Project settings** ← التمرير لأسفل حتى **Your apps** ← الضغط على أيقونة الويب `</>` ← تسمية التطبيق بأي اسم ← **Register app**. يظهر كائن `firebaseConfig` يحتوي على قيم مثل apiKey و projectId.
8. فتح `assets/firebase-config.js` في الموقع ووضع نفس القيم مكان القيم الحالية لكل سطر، ثم الحفظ.
9. رفع كل الملفات (بما فيها `assets/firebase-config.js` المعدَّل) على GitHub بنفس الطريقة المعتادة (Add file → Upload files → Commit).

بعد ذلك يصبح الموقع جاهزًا بالكامل.

## الخطوة ٢: كيف يعمل فريق المحتوى (في كل مرة)

1. فتح رابط `.../editor.html` (ضمن نطاق الموقع نفسه).
2. تسجيل الدخول بالبريد الإلكتروني وكلمة المرور من الخطوة ١-٦.
3. **الصفحة الرئيسية**: تعديل الترحيب، اسم الجهة، السنة، وجهات الاتصال — كل خانة فيها مثال بلون رمادي فاتح يوضّح الشكل المطلوب.
4. **الأيام والفعاليات**:
   - **التاريخ**: اختيار التاريخ الميلادي من التقويم مباشرة (بدون كتابة يدوية) — يملأ الموقع تلقائيًا اسم اليوم بالأسبوع والتاريخ الهجري المقابل، ويمكن تعديلهما يدويًا إذا لزم.
   - **لون اليوم**: اختيار من مجموعة ألوان جاهزة بأسماء عربية طبيعية (كحلي، أزرق مخضر، أخضر زيتوني...)، أو الضغط على "+" لاختيار أي لون آخر من منتقي الألوان الكامل.
   - **الفعاليات**: زر "+ إضافة فعالية" لكل يوم. خانة "تصنيف الفعالية" حرة تمامًا — يُكتب فيها أي نص (تحرك، تجمع، وجبة، أو أي تسمية أخرى)، ويظهر كما كُتب بالضبط تحت عنوان الفعالية. اختيار الأيقونة المرئية (الدائرة الملوّنة) منفصل تمامًا ويكون من شبكة أيقونات صغيرة أسفل خانة التصنيف.
   - لصق رابط خرائط قوقل في خانة "رابط الموقع" يضيف أيقونة موقع قابلة للضغط على الصفحة العامة.
5. زر **معاينة** يعرض الشكل النهائي تمامًا كما يظهر للحضور.
6. زر **نشر التحديثات** ينشر التغييرات فورًا — الرابط نفسه الذي يستخدمه الحضور يتحدث تلقائيًا دون الحاجة لإرسال رابط جديد.
7. زر **تصدير PDF** يفتح نافذة طباعة المتصفح لحفظ نسخة PDF من كامل الجدول بنفس تصميم الموقع تمامًا (الألوان، البطاقات، شارات الوقت)، مع إبقاء روابط المواقع قابلة للضغط داخل ملف الـ PDF نفسه.

## ملاحظات عامة
- لا حاجة لتعديل `assets/style.css` أو `assets/main.js` أو `assets/data-store.js` — هذه التصميم والبنية الثابتة فقط.
- الشعار الرسمي موجود بالفعل في `assets/logo.png`. لتغييره، يكفي رفع صورة PNG بنفس الاسم فوقه من GitHub.
- كل التعديل يتم بالكامل داخل `editor.html`، ولا حاجة لملفات CSV بعد الآن.
